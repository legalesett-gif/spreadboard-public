# Funding navigation exclusion across collector callers

Source review after the observed funding-navigation/websocket overlap found two remaining call paths: the independent FundingCatalogPublisher invoked navigation without the collector heavy lock or websocket pause, and the bulk-funding scheduler held the lock but did not pause websocket. This candidate fixes both and includes the preceding history-path fix 0b534e5.

The independent publisher receives the existing RefreshLoop from collector bootstrap. After a successful catalogue publication, it obtains the collector heavy lock and pauses websocket only for funding navigation. The scheduled bulk-funding callback uses its route publisher's existing refresh loop inside the same heavy lock, after both route-priority checks. Both contexts restore websocket on normal return and failure. Callers without a refresh loop retain their previous behavior; normal collector bootstrap is explicitly tested to supply the actual instance.

Lock review: the independent catalogue call completes and releases its catalogue-build lock/heavy-child semaphore before acquiring the collector lock for navigation. Navigation uses its existing nonblocking build lock and bounded child semaphore. Other normal navigation entry points already own the collector lock (post-discovery, history and scheduled paths). This adds no inverse lock acquisition. The websocket context is evaluated after acquiring the heavy lock, preventing another heavy publisher from resuming websocket within this publication. Catalogue/network collection itself is not placed inside the new pause. Bulk quote collection remains independent.

Regression coverage: four cases exercise both actual callers, success and raised navigation failure, asserting exclusion, force semantics and finally restoration/lock release. The scheduled callback is captured and run synchronously to make exceptions observable. All four fail when the original run/scheduler methods are restored. Existing bootstrap coverage now asserts identity of the wired refresh loop. Prior cold/due scheduler priority tests remain in the suite.

Tradeoff: every real funding-navigation build now extends the optional websocket pause; the existing timeout (default 900 seconds), headroom guard, cadence, retry and publication checks are unchanged. Current bulk quote freshness and all-source pricing must be verified after release. This code closes reviewed call paths, not proof of zero brief production overlap or delivered RAM savings. Catalogue generation itself and other optional workers remain separate memory contributors.
